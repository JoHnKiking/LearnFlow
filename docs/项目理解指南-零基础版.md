## 1. 先搞懂：LearnFlow 到底是个什么东西

**一句话概括**：LearnFlow 是一个手机 App，帮你把"学一个新技能"变成玩游戏——有 AI 帮你规划学习路线，有数字怪兽陪你学，学完还能玩小游戏恢复体力。

**举个具体的例子**：

> 假设你想学"前端开发"。你打开 App，输入"前端开发"，AI 会自动帮你生成一棵"技能树"——先学 HTML → 再学 CSS → 再学 JavaScript → 最后学 React。每个节点都有 B站、慕课网的学习链接。你点开一个节点开始学习，你的数字怪兽就会消耗体力陪你学。学累了？玩一局数独或推箱子小游戏，恢复体力和能量。

**这个 App 的核心功能**：

| 功能 | 说明 |
|------|------|
| AI 技能树 | 输入一个领域（如"前端开发"），AI 自动生成学习路径 |
| 数字怪兽 | 选一只怪兽陪你学习，学习消耗体力，游戏恢复体力 |
| 番茄钟 | 25/45/60 分钟计时器，帮你专注学习 |
| 迷你游戏 | 数独 + 推箱子，玩了能恢复体力/能量 |
| 学习笔记 | 随手记学习心得，怪兽还会给你评论 |
| Pro 会员 | 付费解锁更多功能（无限模块、更多体力等） |

## 2. 项目结构：用"开一家餐厅"来理解

把整个项目想象成**开一家餐厅**：

```
LearnFlow/（餐厅）
│
├── mobile/       → 🏠 前厅（顾客能看到的地方：菜单、装修、点餐屏）
│                   手机上的 App，用户看到的所有界面
│
├── server/       → 👨‍🍳 后厨（顾客看不到的地方：做菜、备料、账本）
│                   运行在服务器上的程序，处理数据、验证登录、调 AI
│
├── monitor/      → 📊 店长办公室（监控面板：今天多少客、卖了多少钱）
│                   运营监控后台，独立运行在 3002 端口
│
├── MySQL 数据库  → 📒 账本和仓库（存着所有食材清单、顾客信息、订单记录）
│                   不在代码里，是独立安装的软件
│
└── 各种文档      → 📋 规章制度手册
```

### 2.1 mobile/（移动端 = 前厅）

这是用户手机上跑的 App。用的是 **React Native + Expo** 技术（意思是"用写网页的方式写手机 App"）。

关键文件夹：

```
mobile/
├── app/              → 所有页面（每个文件就是一个屏幕）
│   ├── splash.tsx        → 启动动画页
│   ├── login.tsx         → 登录页
│   ├── register.tsx      → 注册页
│   ├── (tabs)/           → 底部导航栏的三个主页面
│   │   ├── index.tsx         → 首页（学习地图）
│   │   ├── monster.tsx       → 怪兽页
│   │   └── profile.tsx       → 个人中心
│   ├── skill-tree.tsx    → 技能树详情页
│   └── pomodoro.tsx      → 番茄钟页
│
├── src/
│   ├── services/
│   │   └── api.ts        → 和后厨通信的"服务员"（发 HTTP 请求）
│   ├── components/       → 可复用的零件（按钮、弹窗等）
│   ├── utils/            → 工具函数（认证、存储等）
│   └── types/            → 类型定义
│
└── app.json          → App 的配置文件（最重要：里面写了后端服务器的地址）
```

> **关键点**：`app.json` 里的 `extra.apiBaseUrl` 决定了手机 App 往哪里发请求。开发时指向你自己的电脑，上线时指向服务器。

### 2.2 server/（服务端 = 后厨）

这是运行在服务器（或你电脑）上的程序。用的是 **Node.js + Express** 技术（意思是"用 JavaScript 写后端"）。

```
server/
├── src/
│   ├── app.ts             → 入口：程序从这里启动，监听 3001 端口
│   ├── routes/            → 路由：相当于"菜单"，哪个网址对应什么处理
│   ├── controllers/       → 控制器：接到请求后，先做基本检查
│   ├── services/          → 业务逻辑：真正干活的地方（注册用户、生成技能树等）
│   ├── models/            → 数据模型：和数据库打交道（增删改查）
│   └── config/
│       └── database.ts    → 数据库连接配置
│
├── schema.sql             → 数据库的"设计图纸"（建表语句）
├── .env                   → 环境变量（数据库密码、AI 密钥等敏感信息）
└── package.json           → 依赖清单（这个项目需要哪些第三方库）
```

### 2.3 一次请求的完整流程

以"用户登录"为例，走一遍完整流程：

```
用户在手机上输入邮箱密码，点"登录"
        │
        ▼
手机 App（mobile/）
  → api.ts 里的 authService.login() 被调用
  → 通过 axios 发送 HTTP POST 请求
  → 请求地址：http://服务器地址:3001/api/auth/login
  → 请求内容：{ email: "xxx@qq.com", password: "123456" }
        │
        ▼
服务端（server/）
  → app.ts 收到请求，匹配到 /api/auth 路由
  → routes/authRoutes.ts 把请求转给控制器
  → controllers/authController.ts 接手，做参数检查
  → services/authService.ts 真正处理：
      1. 去数据库查这个邮箱存不存在
      2. 比对密码对不对（用 bcrypt 解密比对）
      3. 生成 JWT 令牌（相当于一张"通行证"）
  → 返回：{ token: "eyJhb...", user: { id: 1, username: "张三" } }
        │
        ▼
数据库（MySQL）
  → 执行 SQL：SELECT * FROM users WHERE email = 'xxx@qq.com'
  → 返回用户记录
        │
        ▼
手机 App 收到响应
  → 把 token 存到本地（AsyncStorage）
  → 跳转到主页
```

## 3. 那些吓人的技术名词，其实没那么难

### 3.1 前端相关

| 名词 | 通俗解释 | 在项目里的作用 |
|------|---------|--------------|
| **React Native** | 用 JavaScript 写手机 App 的框架 | 写 App 的所有界面 |
| **Expo** | React Native 的"工具箱"，帮你打包、调试 | 扫码就能在手机上预览 App |
| **Expo Router** | 页面导航系统，文件名就是网址 | `app/login.tsx` → 访问 `/login` 页面 |
| **TypeScript** | JavaScript 的加强版，多了类型检查 | 项目所有代码都用 TS 写 |
| **axios** | 发 HTTP 请求的工具库 | 手机 App 用它给服务器发请求 |
| **AsyncStorage** | 手机上的本地存储（类似浏览器 localStorage） | 存登录令牌、用户信息等 |

### 3.2 后端相关

| 名词 | 通俗解释 | 在项目里的作用 |
|------|---------|--------------|
| **Node.js** | 让 JavaScript 能在服务器上运行的"引擎" | 跑后端代码 |
| **Express** | Node.js 的 Web 框架（帮你处理 HTTP 请求） | 搭建 API 服务 |
| **JWT** | 一张"电子通行证"，登录后发给用户 | 用户登录后拿着它访问其他接口 |
| **bcrypt** | 密码加密工具 | 用户密码不能明文存，要加密 |
| **dotenv** | 读取 `.env` 文件里的配置 | 管理数据库密码、API 密钥等 |
| **nodemailer** | 发邮件的库 | 注册时发验证码邮件 |
| **OpenAI SDK** | 调用大语言模型的库 | 调 AI 生成技能树、怪兽对话 |

### 3.3 数据库相关

| 名词 | 通俗解释 |
|------|---------|
| **数据库** | 一个专门存数据的软件，比 Excel 强大得多 |
| **MySQL** | 最流行的关系型数据库之一 |
| **表（Table）** | 类似 Excel 的一个工作表，每张表存一类数据 |
| **行（Row）** | 表里的一条记录，比如一个用户的信息 |
| **列（Column）** | 表里的一个字段，比如"用户名""邮箱" |
| **主键（Primary Key）** | 每行的唯一标识，类似身份证号 |
| **外键（Foreign Key）** | 关联其他表的字段，比如"用户ID" |
| **SQL** | 操作数据库的语言，比如 `SELECT * FROM users` |

### 3.4 部署相关

| 名词 | 通俗解释 |
|------|---------|
| **服务器** | 一台24小时不关机的电脑，放在机房里，有公网 IP |
| **SSH** | 远程连接服务器的工具，相当于"远程桌面"但用命令行 |
| **端口（Port）** | 服务器上的"门牌号"，3001 是后端服务，3306 是数据库 |
| **Nginx** | 一个"门卫"程序，把外面来的请求转发到后端服务 |
| **PM2** | 进程守护工具，保证你的 Node.js 程序挂了能自动重启 |
| **ngrok** | 内网穿透工具，让你电脑上的服务能被外网访问 |
| **防火墙/安全组** | 服务器的"保安"，决定哪些端口允许外部访问 |

### 4.3 手机 App 怎么知道服务器在哪？

关键在 `mobile/app.json` 这个文件：

```json
{
  "expo": {
    "extra": {
      "apiBaseUrl": "http://119.91.133.45/api"
    }
  }
}
```

- **开发时**：改成你电脑的 IP 或 ngrok 地址，比如 `http://192.168.1.100:3001/api`
- **上线时**：改成服务器的地址，比如 `http://119.91.133.45/api`

手机 App 里所有的网络请求，都会在这个地址后面拼接具体的接口路径。比如：

```
apiBaseUrl = "http://119.91.133.45/api"
请求登录 → 实际发送到 → http://119.91.133.45/api/auth/login
```

## 5. 数据库是什么？MySQL 又是什么？

### 5.1 用 Excel 来理解数据库

你可以把 MySQL 想象成**一个超强的 Excel**：

- 一个**数据库**（database）= 一个 Excel 文件
- 一张**表**（table）= Excel 里的一个工作表（Sheet）
- 一**行**数据（row）= Excel 里的一行
- 一**列**（column）= Excel 里的一列

LearnFlow 的数据库叫 `learnflow`，里面有 12 张"工作表"：

| 表名 | 存什么 | 类比 |
|------|--------|------|
| `users` | 所有注册用户的信息 | 顾客名册 |
| `monsters` | 每个用户的怪兽 | 顾客的宠物档案 |
| `skill_trees` | AI 生成的技能树 | 学习计划书 |
| `domains` | 用户的学习领域 | 学习科目表 |
| `node_progress` | 每个节点的学习进度 | 打卡记录 |
| `study_records` | 番茄钟学习记录 | 学习日志 |
| `notes` | 学习笔记 | 笔记本 |
| `monster_messages` | 和怪兽的聊天记录 | 聊天记录 |
| `rewards` | 游戏奖励记录 | 奖品发放记录 |
| `device_sessions` | 设备登录会话 | 登录记录 |
| `popular_domains` | 热门搜索领域 | 搜索排行榜 |
| `activation_codes` | Pro 会员激活码 | 充值卡 |
| `email_verification_tokens` | 邮箱验证码 | 验证码记录 |

### 5.2 表和表之间的关系

表和表之间有关联，就像 Excel 之间可以用 VLOOKUP 关联一样：

```
users（用户表）
  │  id = 1, username = "张三", email = "zs@qq.com"
  │
  ├──→ monsters（怪兽表）
  │      user_id = 1（指向 users.id），name = "小火龙"
  │
  ├──→ skill_trees（技能树表）
  │      user_id = 1，domain = "前端开发"，nodes = [树结构JSON]
  │
  ├──→ notes（笔记表）
  │      user_id = 1，content = "今天学了HTML基础"
  │
  └──→ device_sessions（设备会话）
         user_id = 1，device_type = "android"
```

> **关键**：所有表都通过 `user_id` 这个"外键"关联到 `users` 表的 `id`。删了一个用户，他名下的所有数据都会自动删除（`ON DELETE CASCADE`）。

### 5.3 数据库怎么安装和使用

**MySQL 是一个独立的软件**，不是项目代码的一部分。你需要：

1. **安装 MySQL**（就像安装 QQ 一样，下载安装包）
2. **启动 MySQL 服务**（它会在后台运行，监听 3306 端口）
3. **导入建表语句**（运行 `schema.sql`，创建数据库和所有表）
4. **让后端连上 MySQL**（在 `.env` 里填写数据库的地址、用户名、密码）

后端代码里有一个 `database.ts` 文件，专门负责和 MySQL 建立连接：

```typescript
// 简化版，实际代码在 server/src/config/database.ts
const pool = mysql.createPool({
  host: '127.0.0.1',      // 数据库在哪台机器上
  port: 3306,              // 数据库的端口号
  user: 'root',            // 用户名
  password: 'Wzy283537!',  // 密码
  database: 'learnflow',   // 连哪个数据库
  connectionLimit: 10,     // 最多同时保持 10 个连接
});
```

后端需要查数据时，就通过这个连接发 SQL 语句：

```sql
-- 查邮箱为 zs@qq.com 的用户
SELECT * FROM users WHERE email = 'zs@qq.com';

-- 插入一条新用户
INSERT INTO users (username, email, password_hash) 
VALUES ('张三', 'zs@qq.com', '加密后的密码');
```

## 6. 本地开发环境搭建（保姆级教程）

### 6.1 你需要准备什么

| 软件 | 干什么用的 | 下载地址 |
|------|-----------|---------|
| Node.js 18+ | 运行 JavaScript 代码 | https://nodejs.org |
| MySQL 8.0+ | 数据库 | https://dev.mysql.com/downloads/ |
| Git | 代码版本管理 | https://git-scm.com |
| Expo Go（手机App） | 在手机上预览 App | 应用商店搜索 "Expo Go" |
| VS Code（推荐） | 写代码的编辑器 | https://code.visualstudio.com |

### 6.2 第一步：安装 MySQL 并建好数据库

#### Mac 上安装 MySQL

```bash
# 用 Homebrew 安装（如果没装 Homebrew，先去 brew.sh 装）
brew install mysql

# 启动 MySQL 服务
brew services start mysql

# 设置 root 密码（第一次安装后 root 没有密码）
mysql -u root
```

进入 MySQL 命令行后，执行：

```sql
-- 设置 root 密码
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'Wzy283537!';
FLUSH PRIVILEGES;
EXIT;
```

#### Windows 上安装 MySQL

1. 去 https://dev.mysql.com/downloads/mysql/ 下载安装包
2. 安装时记住设置的 root 密码（建议设为 `Wzy283537!`，和项目配置一致）
3. 安装完 MySQL 会自动作为 Windows 服务启动

#### 导入数据库表结构

```bash
# 进入项目目录
cd /Users/你的用户名/Documents/github/LearnFlow

# 用 root 用户登录 MySQL，并执行 schema.sql 文件
# Mac：
mysql -u root -p'Wzy283537!' < server/schema.sql

# Windows（PowerShell）：
mysql -u root -p < server\schema.sql
# 然后输入密码
```

这一步做完后，MySQL 里就有了一个叫 `learnflow` 的数据库，里面有 12 张空表。

**验证一下**：

```bash
mysql -u root -p
# 输入密码后进入 MySQL 命令行

USE learnflow;
SHOW TABLES;
# 应该看到 12 张表

EXIT;
```

## 7. 服务器部署全流程（保姆级教程）

### 7.1 为什么要部署到服务器？

本地开发时，后端跑在你自己电脑上，只有你自己（或同一 WiFi 的人）能访问。**部署到服务器后，全世界的人都能访问你的 App 了。**

### 7.2 你需要准备什么

| 东西 | 说明 |
|------|------|
| 一台云服务器 | 比如腾讯云、阿里云的轻量服务器，操作系统选 Ubuntu |
| 服务器公网 IP | 比如 `119.91.133.45`，这是全世界都能访问的地址 |
| SSH 连接能力 | 你的电脑能通过 `ssh root@IP` 连上服务器 |

### 7.3 部署是什么意思？部署做了哪些事？

**部署 = 把你电脑上跑的后端程序，搬到云服务器上，让它 24 小时运行。**

具体要做这些事：

```
第1步：在服务器上装好运行环境（Node.js、MySQL、Nginx、PM2）
        ↓
第2步：把后端代码传到服务器上
        ↓
第3步：在服务器上建好数据库（导入 schema.sql）
        ↓
第4步：配置好 .env 文件（数据库密码、AI 密钥等）
        ↓
第5步：安装依赖、编译代码（npm install && npm run build）
        ↓
第6步：用 PM2 启动后端程序（让它 24 小时跑着）
        ↓
第7步：配置 Nginx 反向代理（让外部通过 80 端口访问）
        ↓
第8步：开放防火墙端口（让外部能连进来）
        ↓
第9步：修改手机 App 的 apiBaseUrl 指向服务器地址
```

### 7.4 一步步来：详细操作

#### 第 1 步：SSH 连接服务器

```bash
# 在你的电脑终端执行
ssh root@119.91.133.45
# 输入服务器密码后，你就"进入"了服务器
# 接下来的所有命令都在服务器上执行
```

> **什么是 SSH？** 就是远程登录另一台电脑。你电脑上的终端现在操作的是远端服务器，不是你自己的电脑了。

#### 第 2 步：安装 Node.js

```bash
# 安装 Node.js 20.x
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs

# 验证
node -v   # 应该输出 v20.x.x
npm -v    # 应该输出 10.x.x
```

> **什么是 apt-get？** Ubuntu 系统的软件安装工具，类似手机上的应用商店，但用命令行操作。

#### 第 3 步：安装 MySQL

```bash
# 安装 MySQL 服务器
apt-get update
apt-get install -y mysql-server

# 启动 MySQL 并设为开机自启
systemctl start mysql
systemctl enable mysql

# 安全初始化（设置 root 密码）
mysql_secure_installation
# 按提示设置密码，建议设为 Wzy283537!
```

设置 root 密码和认证方式：

```bash
mysql -u root
```

```sql
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'Wzy283537!';
FLUSH PRIVILEGES;
EXIT;
```

> **为什么要 `mysql_native_password`？** Node.js 的 mysql2 驱动和 MySQL 8 默认的认证方式不兼容，需要手动改成老的认证方式，否则后端连不上数据库。

#### 第 4 步：安装 PM2

```bash
npm install -g pm2

# 设置 PM2 开机自启
pm2 startup systemd
# 它会输出一条命令，复制粘贴执行
```

> **什么是 PM2？** 你在本地开发时用 `npm run dev` 启动后端，关掉终端程序就停了。PM2 是一个"保姆"，帮你管理程序的运行——程序意外崩溃了自动重启，服务器重启了自动拉起程序。

#### 第 5 步：把后端代码传到服务器

**方式 A：用 Git 克隆（推荐）**

```bash
# 在服务器上
mkdir -p /opt/learnflow
cd /opt/learnflow
git clone <你的仓库地址> .
cd server
```

**方式 B：从你电脑用 rsync 上传**

```bash
# 在你自己的电脑上执行（不是服务器上）
rsync -avz --exclude node_modules --exclude dist \
  /Users/你的用户名/Documents/github/LearnFlow/server/ \
  root@119.91.133.45:/opt/learnflow/server/
```

> **为什么要排除 node_modules 和 dist？** `node_modules` 体积巨大（几百MB），而且在服务器上需要重新安装（因为操作系统可能不同）。`dist` 是编译产物，服务器上会自己编译。

#### 第 6 步：导入数据库

```bash
# 在服务器上
cd /opt/learnflow/server
mysql -u root -p'Wzy283537!' < schema.sql
```

> `schema.sql` 这个文件里写了 `CREATE DATABASE IF NOT EXISTS learnflow` 和所有建表语句，执行一次就把数据库和所有表都建好了。

#### 第 7 步：配置环境变量

```bash
cd /opt/learnflow/server
cp .env.example .env
nano .env   # 用 nano 编辑器打开
```

填入以下内容：

```
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=Wzy283537!
DB_NAME=learnflow

PORT=3001

JWT_SECRET=换一个复杂的随机字符串
JWT_EXPIRES_IN=7d
REFRESH_TOKEN_EXPIRES_IN=30d

LLM_PROVIDER=volcano
LLM_API_KEY=你的火山引擎API密钥
LLM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
LLM_MODEL=ep-20260222221151-l7tjk
```

> `nano` 编辑器的用法：改完后按 `Ctrl+O` 保存，`Enter` 确认文件名，`Ctrl+X` 退出。

#### 第 8 步：安装依赖并编译

```bash
cd /opt/learnflow/server
npm install        # 安装所有依赖包
npm run build      # 把 TypeScript 编译成 JavaScript
```

> **为什么要编译？** 项目代码用 TypeScript 写的，但 Node.js 只能运行 JavaScript。`npm run build` 会把 `src/` 目录下的 `.ts` 文件编译成 `.js` 文件，放到 `dist/` 目录。

#### 第 9 步：用 PM2 启动后端

```bash
pm2 start dist/app.js --name learnflow-server

# 保存当前进程列表（这样服务器重启后 PM2 会自动拉起）
pm2 save

# 查看状态
pm2 status
```

应该看到 `learnflow-server` 状态为 `online`。

验证后端是否正常：

```bash
curl http://localhost:3001/
# 应该返回：{"message":"LearnFlow Server is running!",...}
```

#### 第 10 步：安装并配置 Nginx

```bash
# 安装 Nginx
apt-get install -y nginx
```

创建配置文件：

```bash
nano /etc/nginx/sites-available/learnflow
```

写入以下内容：

```nginx
server {
    listen 80;                          # Nginx 监听 80 端口（HTTP 默认端口）
    server_name 119.91.133.45;          # 你的服务器 IP

    location /api/ {
        # 把 /api/ 开头的请求转发给 3001 端口的后端
        proxy_pass http://127.0.0.1:3001/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

启用配置：

```bash
# 创建软链接，启用这个站点配置
ln -s /etc/nginx/sites-available/learnflow /etc/nginx/sites-enabled/

# 删除默认站点（否则会冲突）
rm /etc/nginx/sites-enabled/default

# 测试配置是否正确
nginx -t
# 应该输出：syntax is ok / test is successful

# 重新加载 Nginx
systemctl reload nginx
```

> **为什么要 Nginx？** 
> 1. 后端跑在 3001 端口，但用户访问时习惯用 80 端口（浏览器默认）。Nginx 在 80 端口接客，转发给 3001。
> 2. 以后要加 HTTPS（小绿锁），也是在 Nginx 上配。
> 3. Nginx 比直接暴露 Node.js 更安全、更高效。

#### 第 11 步：开放防火墙端口

```bash
# 开放 80 端口（HTTP）
ufw allow 80/tcp

# 开放 3001 端口（直接访问后端，可选）
ufw allow 3001/tcp

# 启用防火墙
ufw enable
```

> **还要在云服务商控制台开放安全组！** 
> 腾讯云：控制台 → 轻量服务器 → 防火墙 → 添加规则 → TCP 80 端口
> 阿里云：控制台 → ECS → 安全组 → 添加入方向规则 → TCP 80 端口
>
> **防火墙和安全的区别**：`ufw` 是服务器操作系统层面的防火墙，安全组是云服务商层面的防火墙。两层都要开，缺一不可。

#### 第 12 步：修改手机 App 指向服务器

编辑 `mobile/app.json`：

```json
{
  "expo": {
    "extra": {
      "apiBaseUrl": "http://119.91.133.45/api"
    }
  }
}
```

然后重新启动 Expo 或打包 APK，手机 App 就会连到服务器了。

### 8.5 排错思路

**后端启动失败？**

```bash
# 1. 看日志
pm2 logs learnflow-server --lines 50

# 2. 常见原因：
#    - 数据库没启动 → systemctl start mysql
#    - .env 里密码不对 → 检查 DB_PASSWORD
#    - 端口被占用 → lsof -i :3001
#    - 依赖没装 → npm install
#    - 没编译 → npm run build
```

**手机连不上后端？**

```bash
# 1. 在服务器上测试后端是否正常
curl http://localhost:3001/

# 2. 在服务器上测试 Nginx 是否正常
curl http://localhost/api/auth/test

# 3. 在你电脑上测试能否访问服务器
curl http://119.91.133.45/api/

# 4. 如果上面都不行，检查防火墙和安全组
ufw status                    # 查看防火墙规则
# 去云控制台检查安全组是否放行了 80 端口

# 5. 检查 app.json 里的 apiBaseUrl 是否正确
```

**数据库连接失败？**

```bash
# 1. 检查 MySQL 是否在运行
systemctl status mysql

# 2. 尝试手动登录
mysql -u root -p

# 3. 如果密码不对，重置密码
mysql -u root
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '新密码';
FLUSH PRIVILEGES;
```

## 9. 常见概念速查表

### 9.1 端口使用一览

| 端口 | 服务 | 说明 |
|------|------|------|
| 80 | Nginx | HTTP 默认端口，外部访问入口 |
| 3001 | Node.js 后端 | 后端服务，Nginx 会转发给它 |
| 3306 | MySQL | 数据库，仅本机访问 |
| 3002 | monitor | 运营监控后台（可选） |
| 8080 | Metro | Expo 开发服务器（本地开发时） |

### 9.2 文件作用速查

| 文件 | 作用 | 什么时候要改 |
|------|------|------------|
| `mobile/app.json` | App 配置，含 API 地址 | 切换开发/线上环境时 |
| `server/.env` | 后端环境变量 | 数据库密码、AI 密钥变化时 |
| `server/schema.sql` | 数据库建表语句 | 表结构变化时，重新导入 |
| `server/src/app.ts` | 后端入口文件 | 一般不需要改 |
| `server/src/config/database.ts` | 数据库连接配置 | 一般不需要改 |
| `mobile/src/services/api.ts` | API 请求封装 | 新增接口时在这里加方法 |
| `mobile/src/utils/constants.ts` | 全局常量 | 颜色、怪兽配置等 |

### 9.3 NPM 命令速查

| 命令 | 作用 | 在哪个目录执行 |
|------|------|--------------|
| `npm install` | 安装依赖 | server/ 或 mobile/ |
| `npm run dev` | 开发模式启动后端 | server/ |
| `npm run build` | 编译 TypeScript → JavaScript | server/ |
| `npm start` | 生产模式启动后端 | server/（需要先 build） |
| `npx expo start` | 启动移动端开发服务器 | mobile/ |
| `npx expo start --tunnel` | 启动移动端 + 隧道 | mobile/ |
| `npx eas build -p android --profile preview` | 打包 Android APK | mobile/ |

### 9.4 开发 vs 生产的区别

| 方面 | 本地开发 | 服务器生产 |
|------|---------|-----------|
| 后端启动 | `npm run dev`（ts-node 直接跑 TS） | `pm2 start dist/app.js`（跑编译后的 JS） |
| 数据库 | 本机 MySQL | 服务器上的 MySQL |
| API 地址 | localhost:3001 或 ngrok 地址 | 服务器 IP（通过 Nginx） |
| 进程管理 | 终端关了就停 | PM2 守护，崩溃自动重启 |
| HTTPS | 没有 | 通过 Nginx 配置（可选） |
| 日志 | 直接在终端看 | `pm2 logs` 查看 |
